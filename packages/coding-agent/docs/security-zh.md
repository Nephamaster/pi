# 安全

Pi 是一个本地 coding agent。它以启动它的用户账号的权限运行，并将该用户可写的文件视为处于同一本地信任边界内。

## 项目信任（Project Trust）

项目信任控制 pi 是否加载项目本地的设置、资源、包和扩展。它不是沙箱，也不限制你在某个目录开始工作后模型能让工具做什么。

当 pi 从当前工作目录发现以下任意内容时，会认为该项目有需要信任的资源：

- `.pi/settings.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts` 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或祖先目录中的项目 `.agents/skills`

空 `.pi` 目录不算需要信任的项目资源。

当交互会话在一个有需要信任资源且当前目录或父目录没有已保存决定的项目中启动时，pi 遵循全局设置中的 `defaultProjectTrust`。默认值是 `"ask"`，在有 UI 时会询问是否信任该项目。已保存的决定按规范化目录存储在 `~/.pi/agent/trust.json` 中，当前路径或父路径上最近的已保存在全局默认值之前生效。

信任一个项目允许 pi 加载需要信任的项目资源，包括：

- `.pi/settings.json`
- `.pi` 资源，如扩展、技能、提示模板、主题和系统提示文件
- 通过项目设置配置但缺失的项目包
- 项目本地扩展和项目包管理的扩展

拒绝信任会跳过受保护的资源。除非禁用了上下文加载，否则 `AGENTS.override.md`、`AGENTS.md` 和 `CLAUDE.md` 这类上下文文件无论项目信任与否都会加载。在信任解决之前，pi 只加载上下文文件、用户/全局扩展和 CLI `-e` 扩展。用户/全局扩展和 CLI 扩展可以处理 `project_trust` 事件；第一个返回是/否决定的扩展拥有该决定权。

非交互模式（`-p`、`--mode json` 和 `--mode rpc`）不显示信任提示。在没有适用的已保存信任决定时，`defaultProjectTrust: "ask"` 和 `"never"` 会忽略此类资源，而 `"always"` 会信任它们。使用 `--approve`/`-a` 或 `--no-approve`/`-na` 可以在单次运行中覆盖项目信任。

## 无内置沙箱

Pi 不包含内置沙箱。内置工具可以以 pi 进程的权限读文件、写文件、编辑文件和运行 shell 命令。扩展是以相同权限运行的 TypeScript 模块。包安装、shell 命令、语言服务器、测试命令和其他开发者工具都表现为普通的本地进程。

这是有意为之。Pi 被设计为在本地源码树上操作、调用项目工具链、并与用户现有的开发环境集成。一个部分的进程内沙箱很容易被误解为安全边界，同时仍然依赖宿主 shell、文件系统、包管理器、凭据和扩展代码。真正的隔离需要来自操作系统或虚拟化/容器边界。

项目信任只是一个输入加载守卫。它防止仓库在你批准之前悄悄修改 pi 的设置或扩展。它不会让不受信任的代码、不受信任的提示或不受信任的模型输出变得安全。来自仓库文件、注释、文档、上下文文件或构建输出的提示注入（prompt injection）是本地 agent 的预期风险，pi 无法可靠地防止它。

## 运行不受信任或无人监督的工作

对于不受信任的仓库、你不打算密切监督的生成代码，或无人值守的自动化，请在受控环境中运行 pi。使用容器、虚拟机、micro-VM、远程沙箱或策略控制的沙箱，只包含任务所需的文件和凭据。

常见模式见 [Containerization](containerization.md)：

- 将整个 `pi` 进程运行在容器/沙箱内
- 在宿主机运行 pi，同时将内置工具执行路由到 Gondolin micro-VM
- 只挂载 agent 应访问的工作区路径
- 除非容器需要访问宿主会话、设置和凭据，否则避免挂载宿主机 `~/.pi/agent`
- 只传入最小必需的 API key 或使用短生命周期凭据
- 在任务不需要时限制网络访问
- 在将结果复制回受信任系统之前审查 diff 和输出

如果你把宿主工作区以读写方式绑定挂载，容器或虚拟机内部的写入仍然可以修改宿主文件。需要更强的非预期写保护时，使用只读挂载或将文件复制进/复制出沙箱。

## 报告安全问题

要报告安全问题，请遵循仓库的 [Security Policy](https://github.com/earendil-works/pi-mono/blob/main/SECURITY.md)。不要为安全敏感的披露创建公开 issue。

除非报告证明了真实的权限边界绕过，或展示了 pi 如何授予本地用户原本没有的访问权限，否则本地 agent 的预期行为、缺乏内置沙箱、来自不受信任内容的提示注入，以及用户安装的扩展或技能的行为，通常不在安全边界之内。
