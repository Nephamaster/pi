# 转译策略与内容质量

## 为什么上一版过度压缩不是必要条件

上传的 `src/contracts/agent-card.ts` 中，responsibilities、principles、deliverables 和 promptProfile 的条目都是非空字符串，没有几行或几百字的长度上限。YAML 的块字符串也能够承载方法、步骤、模板和代码。把角色缩成少量能力标签是内容取舍，不是格式要求。

本版保留角色的主要专业使命、规则、作业过程、报告/设计模板、评价维度、沟通和进阶专长。保持 Software Architect 与 Backend Architect、UI 与 UX、API Tester 与浏览器自动化、Security Architect 与 AppSec、统计学家与实验项目经理等边界，不用同一段通用“基于证据工作”覆盖专业内容。

## 不逐字复制的部分

**虚构履历和记忆。** 原文“工作十年”“处理过某金额”“记住所有经验”等是角色拟人化写法，不是实例事实。本版保留专业经验导向，改为只能引用本次实际可用资料和记录。

**组织与外部权力。** 项目经理、支持升级、商业发布等方法继续保留，但在 IPD 内转为受授权的工作产物和交接，不允许角色直接调度、改状态、联系外部或承诺资金。职业领域中的财务/采购预算仍保留，不把它们误删成 Token 预算。

**评价目标。** 原指标继续作为可识别的参考。不用“95% 实验必须显著”“首轮必须找若干缺陷”等要求制造偏差。当前任务的固定准出标准始终独立；示例数字不是绩效事实或普遍行业标准。

**代码示例。** 多个原文示例包含项目局部函数、未定义依赖、混合框架、错误或过度简化断言。本包保留其接口、算法/公式、数据结构和验证方法，不把片段包装成已验证程序。例如 API 的“不是 500 就安全”、并发总时长除请求数、测试代码混用框架、模型校准 p 值、RFM 重叠分支均在对应角色修改记录中说明。

**短源文件补充。** Content Creator 与两个 XR 角色的源文相对短，缺完整实施模板。本版模板和具体作业组织明确标为工程化补充，不声称原文已有。

## 高风险与过时信息

临床主张逐条匹配人群、研究和用途，不能因“论文/专家签字”自动无限定放行。政府卫生合作不等于无监管市场或采购完成。原 FID 等历史指标、财务/隐私/广告政策和 SDK/API 名称需要执行时以有效官方资料确认；本包不宣称完成全部领域的当前法规或 API 审定。

## 从丰富资产到有效上下文

全库只给设计师索引/能力摘要，不能把 42 张完整画像灌入每个节点。节点仅渲染选中的员工画像；固定节点契约和当前输入仍走已有 Pi 原生入口。没有添加另一套历史、记忆、压缩或 Prompt 执行引擎。

完整文字进入上下文只能证明信息可见，不证明模型遵守、工具隔离、评审正确或产物质量提高；后者依赖 Runtime 和实测。
